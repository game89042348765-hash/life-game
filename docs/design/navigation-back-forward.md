# Навигация Назад/Вперёд — внедрённый контракт

8 ноября 2026. Пользователь выбрал верхние Назад слева / Вперёд справа и нижнюю прокрутку четырёх текущих разделов. Последнее уточнение: **не более пяти экранных переходов**. Прежние варианты и демо-концепции сохранены дословно в `docs/history/2026-11-08-before-app-navigation/navigation-back-forward.md`.

## Интерфейс

- Верхние стрелки располагаются по краям, между ними сохранены LIFE / GAME и балансы. Область каждой стрелки 44 px. Высота шапки учитывает перенос крупных сумм; контент отступает от фактической высоты шапки.
- Снизу ровно исходные Главная / Блоки / Квесты / Бонусы. Иконки сближены, малые стрелки по краям прокручивают только горизонтальную полосу. При отсутствии переполнения они неактивны; переход происходит только при нажатии раздела. Прокрутка не добавляет историю и не меняет экран.
- Недоступные верхние стрелки приглушены. Они не уводят на внешний сайт или в историю предыдущего открытия приложения.

## История

- Одна History API для кнопок и браузерных Back/Forward. У записей есть метка текущего открытия, порядковый индекс, страница и ID блока; UI-кэш держит положение/фокус, этап/вид блока и дату/режим календаря. Игровые данные не копируются и не откатываются.
- Хранятся до шести экранных позиций — пять переходов. После Назад Вперёд доступно в той же ветке. Новый переход из середины удаляет ветку Вперёд.
- Открытые окна используют прежний механизм modal-записей; они не считаются отдельными экранами и не предлагаются для повторного открытия через Вперёд. Native Back закрывает верхнее окно; изменённый редактор требует прежнее подтверждение. Отказ оставляет форму/текст на месте. Многошаговый native Back восстанавливает целевой экран после закрытия окна.
- При перезагрузке создаётся новая граница. Старые native-записи не становятся целями кнопок нового сеанса. Если браузер сам возвращается глубже пяти сохранённых позиций, обычное представление открывается без восстановления забытой UI-позиции; кнопки используют известные внутренние границы.
- Ограничение не удаляет задания, календарные записи, этапы, награды или покупки. Оно относится только к возврату между экранами. История не входит в игровой JSON.
- При запрете History API (в том числе некоторыми file-контекстами) обычные переходы разделов остаются рабочими, стрелки неактивны. Ошибка истории не делает сохранение прогресса неуспешным.

## Проверки агента

Изолированный Chromium, вымышленные данные: 320/390/430 px, пять переходов/границы/ветвление, native Back/Forward, перезагрузка и прежний сеанс, прокрутка списка/дата календаря, модальное сохранение/отмена/отказ выхода из грязной формы, многошаговый Back с окном, четыре нижних раздела и переполнение без перехода, крупные балансы 320 px, недоступный History API. Дополнительно старое сохранение с прежними журналами и native-возвратом за UI-кэш. JS-ошибок, внешних запросов, пропавших ресурсов нет. Физический iPhone/системный жест и приёмка пользователя отдельно.

Временные сценарии `/tmp/check-app-navigation*.py`, снимки `/workspace/visual-review/app-navigation/`. Прежнее отдельное `demo/navigation-controls.html` сохраняет шесть демонстрационных разделов; это материал выбора, не число разделов приложения.
