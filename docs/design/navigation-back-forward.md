# Назад и вперёд — предложение, без внедрения

8 ноября 2026. Пользователь попросил придумать общую кнопку возврата. Это концепция для согласования; код навигации в этой задаче не меняется.

## Форма

Стрелка влево слева от LIFE / GAME в верхней панели, область нажатия не меньше 44 px. Она возвращает по реальному маршруту пользователя, а не всегда к родительскому разделу. Нижние четыре раздела остаются прежними. На стартовом экране без внутренней истории стрелка неактивна или скрыта.

Вперёд — вторичный элемент только при доступной внутренней записи, возможно в меню/по удержанию Назад. На первом этапе разумно проверить одну стрелку Назад. Это рекомендация, не принятое продуктовое решение.

## Поведение

1. При открытом окне сначала закрывает верхнее окно; в изменённом редакторе применяется существующая защита несохранённого ввода. Выбор даты без подтверждения не меняется.
2. Затем возвращает к предыдущему экрану, выбранному блоку/этапу, фильтрам и позиции прокрутки. Черновик быстрого добавления сохраняется по действующему контракту.
3. Назад/Вперёд меняет только представление, не отменяет задания, награды, переносы или другие записи.
4. Новое действие перехода после Назад сбрасывает ветку Вперёд. Повторные рендеры, ввод текста и переключатели формы не создают лишних экранов истории.
5. Кнопка ограничена внутренней историей приложения: не уводит на внешний сайт. После reload нужно безопасно восстановить границы или использовать внутренний запасной переход.
6. Стрелка, браузерный Back/Forward и жест iOS должны работать с одним механизмом, не с параллельными стеками.

## Уже есть в коде

`uiHistoryState`, `uiWriteHistory`, `uiSyncDialogs` и popstate используют History API, учитывают окна и несохранённый редактор; `uiCapture` запоминает положение/фокус. Следующий этап — проверить эти основания, границы внутренней истории и хранение UI-состояния для отдельных записей, затем добавить кнопку поверх общего механизма. Не запускать слепой `history.back()` без проверки границ.

## Приёмка будущей реализации

Главная → Блоки → блок → редактор → Назад: закрыт редактор, далее блок, список, главная. Аналогично календарь, виджеты, Конструктор и вложенные окна. Проверить прокрутку, черновик, несохранённую форму, возврат после переноса, reload/первый запуск, браузерные жесты, границы внешней истории и отсутствие изменений экономических журналов.

## Варианты для следующего обсуждения

1. **Стрелка в верхней панели — рекомендация.** Слева от LIFE / GAME; Вперёд появляется рядом только при доступной внутренней истории. Всегда находится в одном месте, не занимает отдельную полосу. Пример: Блоки → Здоровье → цель; Назад закрывает цель и возвращает к прежней позиции блока, ещё Назад — к списку блоков. Вперёд возвращает к просмотренному блоку.
2. **Плавающая пара ‹ › над нижним меню.** Удобнее дотянуться большим пальцем; скрывается с клавиатурой и модальным окном. Пример: Конструктор → задание в блоке → Назад возвращает к тому же месту Конструктора. Ограничение: конкурирует за место с сохранением/нижними действиями и может закрывать контент.
3. **Контекстное «← К списку» под заголовком.** Всегда понятно назначение: «К блокам», «К Конструктору». Пример: из Бонусов в покупку и обратно к Бонусам. Ограничение: возвращает к родительскому разделу, а не по реальному пути; не решает универсальное Вперёд и возвращение из переходов между виджетами.

Для первого этапа предлагается вариант 1. Состояния для наглядного демо: старт без стрелок; после перехода только Назад; после Назад обе стрелки; открытое окно — Назад закрывает его; черновик — сохраняется или срабатывает существующее подтверждение. Внедрение ещё не согласовано; эти примеры не описывают уже работающую кнопку.

## Текущее демо по уточнению пользователя

`demo/navigation-controls.html` теперь объединяет два разных действия: сверху Назад слева / Вперёд справа для истории экранов, снизу маленькие стрелки слева/справа только для горизонтальной прокрутки разделов. Прежний переключатель вариантов убран. В нижней полосе шесть пунктов, по три видимых: Главная / Блоки / День / Календарь / Квесты / Бонусы. Три дополнительных экрана — простые демонстрационные представления без реальных функций.

Прокрутка иконок стрелкой или свайпом не открывает раздел, не меняет экран и History API. Переход происходит только при нажатии иконки; выбранная иконка автоматически попадает в видимую область при истории Назад/Вперёд. Недоступные стрелки приглушены. Визуально нижние стрелки 14 px, область нажатия 44 × 48 px. Это демо формы; основной код приложения не изменён. Первое сравнение двух расположений сохранено в Git и docs/history.
