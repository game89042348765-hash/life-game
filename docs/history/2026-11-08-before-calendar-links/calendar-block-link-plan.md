# Календарные дела и блок времени — план следующего изменения

8 ноября 2026. Направление предложено пользователем. Этот файл — проект поведения и проверки; календарная модель и интерфейс в текущей задаче НЕ изменены.

## Одна запись, несколько мест отображения

Календарное дело остаётся единственной `calendarEntries` с прежним ID, датой/временем, наградой и фактом выполнения. Добавляется необязательный `blockId` (null по умолчанию). В календаре виден привычный тег блока, как у задания; нажатие ведёт к этой записи в блоке. Без блока поведение прежнее.

Внутри блока — служебная секция «Запланированное», визуально близкая к этапу, но без целей и смысла. Она показывает связанные календарные записи, а не создаёт копии задач. Это не элемент `blockStages`: не становится текущим, не блокируется прохождением, не влияет на оптимальный этап и не участвует в зависимостях. При создании/переходе этапов календарные дела не переезжают и не удаляются.

Служебную секцию предлагается размещать рядом с рабочим содержимым блока, с количеством и сворачиванием. Точное место в лестнице лучше проверить на демо перед большим внедрением: уже существующий настоящий этап «Планируемый» нельзя смешивать с календарной секцией.

## Ввод и редактирование

- Быстрое добавление: при выборе календарной даты поле блока остаётся доступным; без выбора — null. После успешной записи форма сбрасывается как сейчас. Сегодня без выбора даты по-прежнему создаёт обычное задание в плане.
- Обычный редактор календаря: необязательный список активных блоков, возможность убрать связь. При редактировании записи с архивным блоком старую связь можно увидеть/снять, не потеряв её молча.
- Перенос в другой блок меняет только связь, не ID/дату/время/награду/факт выполнения. Перенос даты не превращает запись в обычное задание. Повторы календарных записей отдельно не добавляются.
- На карточке один тег блока; дата остаётся датой. Привязки к цели и этапу нет. При нажатии тега не переключать текущий этап блока.

## Все места приложения

1. Полный календарь, Конструктор (календарная секция), Выполнено, итог/история: один и тот же источник и привычные действия. В Конструкторе нет второй копии в секции Задания.
2. Блок: группы Сегодня / Далее, незавершённые старые записи не прятать — отдельная группа «Ранее». Выполненные в свёрнутой истории. Сортировка по дате/времени с существующими правилами избранного. Никаких целей/смысла внутри секции.
3. Счётчики блока: предложено общее «Дел / На сегодня» с учётом незавершённых календарных записей, без двойного подсчёта. Это текстовое решение ещё нужно принять при просмотре демо.
4. Выполнение и отмена из любого представления работают с прежними `calendarCompletions`/монетными записями. Награда начисляется один раз, при reward=0 сохраняется факт. Перенос/привязка не начисляют ничего; потраченные монеты защищаются прежним подтверждением. Правила бонуса дня не расширяются самовольно.
5. Архив блока: календарное дело остаётся в календаре и доступно там; тег показывает архивный блок. В архивный блок нельзя добавлять новые связи. Восстановление возвращает отображение секции. При окончательном удалении блока связь снимается, календарная запись/факты/дата остаются; удаление блока не удаляет календарь каскадом.
6. Удаление календарной записи сохраняет существующую политику истории/начислений. После удаления нет «висящей» копии в блоке. Старые теги/переходы ведут безопасно к доступному представлению, а не к пустому экрану.
7. JSON/нормализация: отсутствие blockId у старой записи → null. Ссылка на существующий архивный блок допустима, неизвестный/неправильный тип не принимается молча. Импорт атомарный. Действующий ключ/ID/журналы сохраняются. Новый код и обратимость схемы описываются до внедрения.
8. Навигация и поиск цели карточки: сохранить отображение календарной секции при Назад/Вперёд; тег открывает нужный блок и прокручивает к записи. Блок/этап, недоступные после архива/удаления, не ломают историю.
9. Фильтры/избранное, состояние сворачивания, маленький отклик добавления, уведомления об ошибках, мобильная разметка и экранная клавиатура используют принятые правила.

## Порядок работы

1. Уточнить расположение служебной секции и счётчиков коротким демо на 1–2 блоках.
2. Добавить необязательную связь, проверку/импорт и политику архива/удаления с тестами без UI-дубликатов.
3. Подключить оба редактора, теги и секцию блока к общим карточкам календаря.
4. Проверить все представления, экономику/отмену и возврат, затем публиковать.

## Приёмка

Без блока / с блоком; дата сегодня/будущая/прошлая; 0/25 и пользовательская награда; выполнение из блока, отмена из календаря и наоборот; точное восстановление журналов и запрет двойной оплаты; перенос даты/блока/снятие связи; смена текущего этапа; архив/восстановление/окончательное удаление блока; удаление записи; JSON старый/новый/невалидный; конфликт вкладок/quota/смена дня; теги/фильтры/избранное/счётчики/Назад; 320/390/430 px. Реальные данные не подменять фикстурой.
