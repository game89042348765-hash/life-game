# LAB-004A — восстановление стенда после прерывания

Готовое задание одной внешней модели с запуском кода/браузера. Если инструментов нет, вернуть патч и явно отметить невыполненные проверки. Область исключительно лабораторная инфраструктура; не менять приложение и не запускать платные API.

Прочитай `LABORATORY_HANDOFF.md`, `personal-lab/AGENTS.md`, `research/LAB-002-digital-month/driver.py`, README-DRIVER.md, SCALE.md и переносимый INDEX.md. Работай с актуальной веткой `lab/synthetic-users`; запиши точный SHA и SHA-256 driver перед правкой. Изменённые файлы одновременно принадлежат только одному исполнителю.

## Проблема и результат

Транспорт сохраняет реальные Chromium profiles и журналы, но новый daemon отказывается открывать существующий run-dir. Для 16×30 дат прерывание может потерять оперативную память оркестратора и спровоцировать повтор UI-действия. Нужен явный режим возобновления, сохраняющий историю, а не создающий её заново.

Добавь checkpoint/resume для actor/day, собственных заметок, последней завершённой даты, расхода бюджета, статуса активной сессии и виртуального времени. После закрытого дня продолжать следующий. После no_use не открывать приложение задним числом. Проверять соответствие мира и версии приложения; несовпадение не исправлять молча.

Не обещай exactly-once для произвольного сбоя между реальным UI-коммитом и записью ответа в журнал. Такой pending-action должен оставаться явно неоднозначным: безопасно восстановить наблюдение и сообщить исполнителю о необходимости сверки. Автоматически повторять click/submit/покупку нельзя. Незавершённые черновики и обрыв trace не выдавать за полностью восстановленные.

Сохранять старые события/trace и писать продолжение отдельно. Защитить от одновременного открытия одного profile двумя daemon. Освобождение контекста завершённого actor желательно без потери persisted данных. Перезапуск на закрытом полном run должен безопасно отказываться либо оставаться только для чтения.

## Разрешённые файлы

`personal-lab/research/LAB-002-digital-month/driver.py`, README-DRIVER.md и небольшие проверки рядом. `app.js`, persistence.js, planning.js, sw.js, HTML/CSS, существующие evidence и профили исходного пилота не менять. Новые прогоны — в отдельном игнорируемом verification-каталоге.

## Критерии приёмки

1. Настоящее создание через UI → конец дня → остановка daemon → resume → следующий день: данные сохранены, прежнее действие не повторено.
2. Память и счётчики двух разных акторов не смешиваются, обе виртуальные даты верны.
3. Пропущенный день остаётся no_use после перезапуска; расход бюджета не обнуляется для активной сессии.
4. Прерывание после действия, но до подтверждения, явно показывает неоднозначность и не вызывает повтор автоматически. Нельзя подменить эту проверку чистым JSON-тестом.
5. Несовпадение мира/версии, занятый profile и завершённый run обрабатываются с понятной причиной и без перезаписи доказательств.
6. Старый обычный запуск и новый resume выполняют настоящие UI-действия; snapshots, trace-продолжения и схема состояний проверены. Контроль ошибок сохраняется.

Верни unified diff, команды и фактические результаты, пути артефактов и оставшиеся ограничения. Полный месяц не запускать в этом задании. Не приписывать техническому smoke статус нового пользовательского исследования. Язык краткого отчёта — русский; не возвращай целое приложение вместо патча стенда.
